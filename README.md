# Voyago — программное средство поддержки бизнес-процессов туристической компании

Курсовой проект по дисциплине «Программирование сетевых приложений» (БГУИР).
Клиент–серверное приложение на Java: многопоточный сервер, клиент на JavaFX, СУБД MySQL 8.
Интерфейс на двух языках (RU / EN), цены в BYN.

## Требования

- JDK 21
- MySQL 8 и MySQL Workbench
- Интернет при первой сборке (Maven и библиотеки скачаются автоматически)

## Структура

```
tour-agency/
├── common/   общие классы: модели, протокол Request/Response, исключения
├── server/   многопоточный сервер, JDBC, бизнес-логика
├── client/   оконное приложение JavaFX
├── db/       скрипт генерации БД, демо-данные и их генератор (gen_demo_data.py)
├── mvnw.cmd  сборка без установки Maven (Windows)
├── run-server.cmd
└── run-client.cmd
```

## Развертывание

1. **База данных.** В MySQL Workbench выполните по очереди (кнопка с молнией):
   `db/tour_agency_db.sql` — структура и справочники, затем `db/demo_data.sql` — демонстрационные
   данные (8 стран, 18 городов, 22 отеля, 30 туров, 15 клиентов, 29 бронирований, отзывы, уведомления).
2. **Настройки сервера.** В `server/src/main/resources/server.properties` укажите
   пользователя и пароль MySQL (`db.user`, `db.password`). Без пересборки настройки можно
   переопределить файлом `server.properties` рядом с проектом или аргументами:
   `run-server.cmd --db.password=мой_пароль --server.port=6000`.
3. **Сборка:** в корне проекта выполните
   ```
   mvnw.cmd clean package
   ```
4. **Запуск:** сначала `run-server.cmd`, затем `run-client.cmd` (можно запустить несколько клиентов).

| 2 | Анкета предпочтений (8 шагов): страны, бюджет, даты, ночи, тип отдыха, звёзды, питание, состав | клиент |
| 2 | Подбор туров: процент совпадения 0–100 % с объяснением по каждому критерию, сортировка «по совпадению» | клиент |
| 2 | Рекомендации: подборка по анкете + учёт истории поездок и избранного | клиент |
| 2 | Избранное (сердечко на карточке тура) | клиент |
| 3 | Бронирование: туристы, автоматический выбор наибольшей скидки, защита от «гонки» за последнее место | клиент |
| 3 | Мои бронирования: этапы заявки, оплата, отмена с расчётом штрафа по шкале, отзыв после поездки | клиент |
| 3 | Уведомления: смена статуса заявки, новый тур с совпадением ≥ 60 %; колокольчик в шапке | клиент |
| 3 | Бронирования: фильтр по статусу, поиск, карточка заявки, смена статуса по допустимым переходам, отмена | менеджер, админ |
| 4 | Панель управления: показатели, графики продаж и бронирований, заявки, ожидающие обработки | менеджер, админ |
| 4 | Аналитика за период: выручка, страны, направления, отели, рейтинги, скидки, статусы; экспорт в Excel и PDF | менеджер, админ |
| 4 | Пользователи: поиск, смена роли, блокировка/разблокировка | админ |
| 4 | Журнал действий с фильтрами по действию, объекту и датам | админ |

Бизнес-правила на сервере: нельзя уменьшить число мест ниже забронированного, удалить тур
с бронированиями, создать тур в прошлом, задать скидку без условий; дубликаты названий отклоняются.
Бронирование: только взрослый в составе, места проверяются под блокировкой строки (`SELECT … FOR UPDATE`),
статус «Поездка завершена» — только после даты окончания, штраф за отмену берётся из настройки
`penalty.scale` (дней до вылета : процент) и начисляется только за оплаченную заявку.

### Демонстрационный сценарий

1. `client` → «Моя анкета» → изменить бюджет → «Рекомендации» — проценты пересчитались.
2. Открыть тур → «Как считается совпадение» → «Забронировать» — видна применённая скидка.
3. `manager` → «Бронирования» → новая заявка → «Изменить статус» → «Ожидает подтверждения».
4. `client` → колокольчик показывает уведомление о смене статуса.
5. `admin` → «Аналитика» → «С начала года» → Excel / PDF; «Журнал действий» — все шаги выше.

## Реализованные требования

| Требование | Где реализовано |
|---|---|
| Многопоточный сервер | `Server` (пул потоков `ExecutorService`), `ClientHandler` |
| Настройки без изменения кода | `ServerConfig`, `ClientConfig` (файл + аргументы командной строки) |
| Доступ к БД через JDBC | `ConnectionPool`, `BaseDao` и `Jdbc*Dao`; транзакции — `BaseDao.inTransaction()` |
| Авторизация и роли | `AuthService`, `AbstractCommand.allowedRoles()`; роли: администратор, менеджер, клиент |
| Иерархия классов | `Entity` → `User`, `Country`, `City`, `Hotel`, `Tour`, `Discount`, `DictionaryItem`; `AppException` (extends `Exception`) → `ValidationException`, `AuthException`, `NotFoundException`, `BusinessRuleException`; `DataAccessException` (extends `RuntimeException`); `AbstractCommand` → команды; `BaseView` → `AuthView` → `LoginView`/`RegisterView`, разделы; `EditDialog` (extends `Dialog`) → формы; компоненты, расширяющие JavaFX: `TourCard` (VBox), `CountryCard` (StackPane), `Badge` (Label)… |
| Паттерн Singleton | `ConnectionPool`, `ServerConnection` |
| Паттерн Factory | `CommandFactory` |
| Паттерн Command | `Command` и его реализации |
| Паттерн Template Method | `AbstractCommand.execute()` → `doExecute()`; `EditDialog` → `collect()` / `saveRequest()` |
| Паттерн Observer | `EventPublisher` → `NotificationService` (новый тур, смена статуса); `I18n` — подписчики на смену языка перестраивают окно |
| Паттерн Strategy | `DiscountStrategy` → `SeasonalDiscountStrategy`, `EarlyBookingDiscountStrategy`, `LoyaltyDiscountStrategy`; выбирает `DiscountCalculator` |
| Инкапсуляция | закрытые поля моделей с геттерами/сеттерами |
| Перегрузка методов | `Response.ok(...)`, `Request.getString(...)`, `I18n.t(...)`, `Fmt.money(...)`, `Validator.requireNot…`, `ServerMessages.get(...)`, `Async.send(...)` |
| Переопределение методов | `doExecute()`, `allowedRoles()`, `getDisplayName()`, `build()`, `equals/hashCode/toString` |
| Сериализация | `Entity`, `Request`, `Response` передаются через `ObjectOutputStream` |
| Интерфейсы и абстрактные классы | `Command`, `Shell`, `*Dao`; `Entity`, `AbstractCommand`, `BaseDao`, `BaseView`, `AuthView`, `EditDialog` |
| Статические методы | `PasswordHasher`, `Validator`, `ServerMessages`, `Fmt`, `I18n`, `Ui`, `Response.ok/error` |
| Обработка исключений | `ClientHandler.handle()`, try-with-resources в DAO |
| Хранение паролей | SHA-256 с солью (`PasswordHasher`) |
